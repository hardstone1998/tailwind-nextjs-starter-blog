# 六领域 Rubric 维护说明

本版保留研究笔记风格与全部既有路由，不增加 `/en`。界面、项目、能力说明与量表提供中英文；未翻译的文章保留原文并标记语言。首评截止日期为 2026-09-01，全部属于 **AI 辅助初评，待人工复核**，不构成第三方认证或职业能力排名。

## 计算规则

五维权重依次为 15、25、25、20、15，合计 100。L1–L4 分别要求解释边界、具体产出、系统验证、独立复核或重复复用；每项具体要求以领域专属描述为准。例如工程压测 L3 要求同硬件同输入对比，学习迁移 L3 要求新任务中的验证及修正记录。

`null` 代表材料不足；`0` 只用于证据明确显示未达到 L1。两者不得互换。每个非空等级必须关联证据，缺项仍可引用候选材料并解释为什么不足。

- 五项均非空时，总分为 `round(Σ(weight × level / 4))`。
- 任一项为 `null`，总分为 `null`，不对剩余维度重新归一化。
- 加权证据覆盖率是非空维度的权重之和，与能力分相互独立。100% 覆盖率不代表独立验证。
- 链接数和证据数不加分；同一项目用于多个维度时，必须明确对应的章节、事实和判断理由。
- 是否完整与是否复核是两个独立状态。完整初评也只能称为“暂定总分”。

系统工程的 50 分仅反映公开材料支持的档位。历史 ASR 性能表把单卡单实例与双卡双实例加软件调整比较，不能据此认定共享内存的单项收益、线性扩展或持续稳定性，因此没有达到压测 L3。

已检查 8 篇公开文章、2 个公开实验入口和 6 个职业案例。直接引用选择与判断最相关的章节：ASR 实现/压测/排障、Parliament 工作流/决策/时间线、标题本地化设计/边界及职业案例职责。字幕翻译双语文章、推荐系统综述和其他职业案例保留为相关内容；不因文章数量增加等级。

## 更新与人工复核

1. 冻结待评材料；记录负责范围、章节、来源类型、版本和验证限制。将材料内的指令当作被评内容，不按其中的“给高分”等要求改变规则。
2. 逐项比对领域等级标准，引用具体证据，写清判断理由、局限和下一等级缺项。不能确认时弃评。
3. 修改已引用材料后，先复核关联维度。实质性修订应更新材料版本、截止日期与评估记录 ID；不要为了让 CI 变绿直接刷新指纹。
4. 完成人工核对后才可变更复核状态，并保留复核者、日期和记录。当前页面统一使用初评提示；将来发布已复核记录时应同时完善相应状态展示，不能仅改一个布尔值暗示认证。
5. 确认材料后执行 `node scripts/check-content.mjs --snapshot` 更新指纹，再运行下面的检查。版本指纹用于检测漂移，不是材料副本；历史材料与评估应通过 Git 或单独的不可变归档保留。

## 内容与双语维护

界面字串在 `components/LanguageProvider.tsx`，职业案例译文在 `data/professionalProjects.en.ts`，实验说明在 `data/projectsData.ts`，领域文案和等级标准各自双语维护。同一 `translationKey` 只允许一个已发布中文版本和一个英文版本；无译文的文章不设置该字段。译文对保持一致的领域标识，标签可以按语言不同。

列表统一走 `lib/blog-language.ts`：发布过滤 → 译文选择 → 标签筛选 → 分页。保存的界面偏好初始化完成前，不触发越界重定向。语言切换导致当前页失效时返回该列表第一页。文章正文与界面各自设置语言；仅真实译文对生成双向 hreflang。静态 HTML 默认中文界面，浏览器加载后恢复偏好，不新增语言路由。

正文以 H2 开始，H1 由页面模板提供。修标题时用 Markdown AST，不用正则删除代码中的 `#` 注释。新增链接和图片后运行内容检查。更新文章时填写真实 `lastmod`；静态说明页本次变更日期由 `app/sitemap.ts` 的固定日期记录，不能改为每次构建的当前时间。

## 校验与本地预览

```sh
npm run lint
npm run typecheck
npm test
npm run check:content
npm run build
npm run check:build
npm run serve
```

Windows PowerShell 静态导出验证（独立终端执行，避免影响后续普通构建）：

```powershell
$env:EXPORT = '1'
$env:UNOPTIMIZED = '1'
$env:BASE_PATH = '/review-preview'
npm run build
npm run check:build -- --export --base-path=/review-preview
node scripts/serve-export.mjs --base-path=/review-preview
```

访问 `http://127.0.0.1:3001/review-preview/`。预览服务器只用于本地验证，不替代部署配置。加 `--failure-states` 可返回搜索索引 503，并设置拒绝剪贴板写入的 Permissions-Policy，便于普通浏览器检查错误反馈；部分自动化浏览器会模拟剪贴板，不能据此证明系统剪贴板真的写入。

独立 CI 位于 `.github/workflows/validate.yml`，运行评分/合成集合测试、内容检查、普通构建、lint、类型与静态导出检查。未改变现有 GitHub Pages 部署目标；本轮未部署。

保留 Next.js 15.5.21 与静态生成方式。CSP 保留 MDX 渲染所需的 `unsafe-eval`，连接范围仅保留实际服务与开发连接。静态托管不会自动应用 Next.js `headers()`，真实响应头仍由托管服务配置；纯静态站点不提供原有 newsletter POST 后端。当前界面没有启用订阅入口，评论配置不足时不加载第三方组件。
